# 03. Модели жизненного цикла

**Статус — модели жизненного цикла согласованы.**

## Назначение документа

- **Задача** — определить состояния объектов, события, условия переходов и действия при переходах.
- **Результат** — модели жизненного цикла бронирования, платёжной попытки, закрепления мест багажа, проверки документа и запроса на возврат.
- **Использование** — согласование концептуальной модели с процессами и последующая проверка транзакций.
- **Признак готовности** — для каждого существенного исхода определены исходное и результирующее состояния, ответственный участник и изменения связанных объектов.

Нотация — диаграмма состояний UML (унифицированный язык моделирования). [Схема состояний](03-lifecycle.svg) применяется совместно с таблицами переходов. Закрашенный круг обозначает начальное псевдосостояние, скруглённый прямоугольник — состояние, стрелка — переход. Код на стрелке соответствует строке таблицы. Символ «∅» обозначает начальную точку. Стрелка «→» отделяет исходное состояние от результирующего.

## Бронирование

| Код | Переход или действие | Событие и условие | Результат |
| --- | --- | --- | --- |
| B01 | ∅ → Ожидает оплаты | Владелец аккаунта подтверждает оформление. Документ пассажира подтверждён, выбранное место свободно, запрошенный багаж укладывается в вместимость. | Создаётся бронирование. Пассажирское место и указанные места багажа закрепляются. Инициируется платёжная попытка. |
| B02 | Ожидает оплаты → Оплачено | Получено подтверждение оплаты билета по данному бронированию. | Оформляется билет. Пассажирское место сохраняется за бронированием. Первоначальное закрепление багажа подтверждается при его наличии. |
| B03 | Ожидает оплаты → Прекращено без оплаты | Получен окончательный результат основной платёжной попытки без оплаты. | Пассажирское место и первоначально закреплённые места багажа освобождаются. |
| B04 | Оплачено → Отменено | Владелец аккаунта подтверждает отмену. Условия покупки допускают отмену, незавершённых платёжных попыток по бронированию нет. | Пассажирское место и закреплённые места багажа освобождаются. При наличии права на возврат можно подать отдельный запрос. |
| B05 | Внутреннее действие в состоянии «Оплачено» | Владелец аккаунта выбирает другое свободное место того же рейса. | Новое место закрепляется и прежнее освобождается одной операцией. При недоступности нового места прежнее закрепление сохраняется. |
| B06 | Внутреннее действие в состоянии «Оплачено» | Владелец аккаунта добавляет багаж, на рейсе имеется необходимая багажная вместимость. | Создаются временное закрепление дополнительных мест багажа и отдельная платёжная попытка. |

При недоступности места, недостаточной вместимости или отсутствии подтверждённого документа событие B01 завершается отказом до создания бронирования. Пока окончательный результат основной платёжной попытки неизвестен, действует состояние «Ожидает оплаты».

## Платёжная попытка

| Код | Переход | Событие и условие | Результат |
| --- | --- | --- | --- |
| M01 | ∅ → Результат ожидается | Приложение инициирует оплату билета или доплату за багаж. | Фиксируются назначение и сумма. Попытка связывается с бронированием и при необходимости с закреплением багажа. |
| M02 | Результат ожидается → Оплата подтверждена | Платёжный сервис сообщает окончательное подтверждение по этой попытке. | Для оплаты билета выполняется B02. Для доплаты за багаж выполняется G02. |
| M03 | Результат ожидается → Попытка завершена без оплаты | Платёжный сервис сообщает окончательное завершение по этой попытке без оплаты. | Для оплаты билета выполняется B03. Для доплаты освобождается только связанное дополнительное закрепление по G03. |

Повторное сообщение о том же окончательном результате сохраняет ранее зафиксированный результат операции. Подтверждение оплаты, оформление билета и подтверждение соответствующего закрепления багажа учитываются согласованно.

## Закрепление мест багажа

| Код | Переход | Событие и условие | Результат |
| --- | --- | --- | --- |
| G01 | ∅ → Временное | Оформляется бронирование с багажом или инициируется добавление багажа. На рейсе достаточно мест багажа. | Запрошенное количество включается в расчёт занятости. |
| G02 | Временное → Подтверждённое | Платёжный сервис подтвердил оплату связанной операции. | Количество включается в оплаченный багаж, продолжая учитываться в занятости рейса. |
| G03 | Временное → Освобождённое | Связанная платёжная попытка окончательно завершилась без оплаты. | Количество исключается из расчёта занятости. |
| G04 | Подтверждённое → Освобождённое | Подтверждена отмена бронирования. | Количество исключается из расчёта занятости. |

## Проверка документа

| Код | Переход | Событие | Результат |
| --- | --- | --- | --- |
| V01 | ∅ → Ожидается результат | Приложение направляет загруженный документ во внешний сервис проверки документов. | Создаётся запись о проверке конкретного документа. |
| V02 | Ожидается результат → Подтверждён | Сервис сообщает положительный результат. | Проверка может служить основанием для оформления бронирования при наличии реквизитов документа. |
| V03 | Ожидается результат → Отклонён | Сервис сообщает отрицательный результат. | Оформление бронирования по результату этой проверки отклоняется. |

Повторное направление документа образует отдельную проверку. Для уже оформленного бронирования сохраняется связь с использованной проверкой.

## Запрос на возврат

| Код | Переход | Событие и условие | Результат |
| --- | --- | --- | --- |
| Q01 | ∅ → Подан | Владелец аккаунта подаёт запрос после подтверждённой отмены. Условия покупки допускают возврат оплаты билета. | Запрос связывается с отменённым бронированием и подтверждённой оплатой билета. |
| Q02 | Подан → Рассматривается | Получены сведения о принятии запроса к обработке. | В личном кабинете отражается состояние рассмотрения. |
| Q03 | Рассматривается → Завершён | Получен окончательный результат рассмотрения. | Фиксируются состояние и момент завершения, а при определении суммы — сумма к возврату. Бронирование сохраняет состояние «Отменено». |

Источником сведений о состоянии запроса является внешний платёжный сервис. Обработка фактического возврата относится к границе ответственности, уточняемой при архитектурном проектировании.

## Условия обработки отмены и возврата

- Отмена допускается после завершения активной платёжной попытки по бронированию. Это условие сохраняет согласованность закреплений с окончательным результатом оплаты или доплаты.
- Приложение фиксирует состояние запроса, полученное от внешнего платёжного сервиса. Способ получения результата и состав передаваемых сведений определяются после выбора сервиса.
