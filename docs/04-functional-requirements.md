# Функциональные требования

`FR-001`: Система **должна** проверять учётные данные при входе в аккаунт и предоставлять доступ к личному кабинету этого аккаунта только после успешной проверки.

`FR-002`: Система **должна** предоставлять владельцу аккаунта возможность добавлять пассажиров в личном кабинете, просматривать список добавленных пассажиров и вносить реквизиты их документов. Данные аккаунта, сведения о личности пассажира и реквизиты его документов **должны** учитываться раздельно.

`FR-003`: Система **должна** предоставлять владельцу аккаунта сведения о рейсах и свободных местах на выбранном рейсе.

`FR-004`: Система **должна** позволять владельцу аккаунта оформить бронирование на себя или на пассажира из своего списка только при наличии реквизитов документа выбранного пассажира и положительного результата внешней проверки этого документа. При оформлении система **должна** закреплять за бронированием свободное место на время оплаты и сохранять указанное количество мест багажа.

`FR-005`: Система **должна** обеспечивать оплату бронирования через внешний платёжный сервис и фиксировать сообщённый им результат. После подтверждения оплаты система **должна** оформить билет на пассажира, указанного в бронировании, и предоставить сведения о билете владельцу аккаунта.

`FR-006`: Система **должна** позволять владельцу аккаунта заменить место в оформленном с его аккаунта бронировании на свободное место того же рейса. При успешной замене система **должна** освободить прежнее место. При недоступности выбранного места система **должна** сохранить прежнее место за бронированием.

`FR-008`: Система **должна** позволять владельцу аккаунта добавить места багажа по билету, оформленному с его аккаунта, после оплаты этого билета. Система **должна** принимать доплату через внешний платёжный сервис и увеличивать количество мест багажа только после подтверждения доплаты.

`FR-009`: Система **должна** предоставлять владельцу аккаунта список бронирований, оформленных с его аккаунта, и сведения о выбранном бронировании, включая его текущее состояние и сведения об оформленном билете при его наличии.

`FR-010`: Система **должна** предоставлять владельцу аккаунта маршрутную квитанцию по билету, оформленному с его аккаунта, для просмотра, печати и отправки по электронной почте.

`FR-012`: Система **должна** позволять владельцу аккаунта отменять бронирование, оформленное с его аккаунта, при соблюдении условий отмены. После подтверждения отмены система **должна** освобождать закреплённое место.

`FR-013`: Система **должна** позволять владельцу аккаунта подавать запрос на возврат оплаты по отменённому бронированию, оформленному с его аккаунта, если условия приобретения билета допускают возврат, и предоставлять сведения о состоянии запроса.

`FR-014`: Система **должна** обеспечивать регистрацию через сервис регистрации. После подтверждения успешной регистрации система **должна** создавать аккаунт приложения, связанный с зарегистрированной учётной записью для последующего входа.

`FR-015`: Система **должна** позволять владельцу аккаунта загружать в личном кабинете документы для себя или для пассажира из своего списка, направлять загруженные документы во внешний сервис проверки документов и сохранять полученный результат проверки для каждого документа.

`FR-016`: Система **должна** учитывать для каждого рейса отдельно предельное количество пассажирских мест и мест багажа и предотвращать превышение соответствующего предела при оформлении бронирования и добавлении багажа.
