# Цели заказчика и обоснование состава функций

**Статус — проектное обоснование.**

## Назначение документа

- **Задача** — определить ожидаемый результат для заказчика и основания для приёмки.
- **Результат** — связь деловых целей с функциями, сценариями и наблюдаемыми результатами.
- **Использование** — оценка полноты проектируемой системы и подготовка программы испытаний.
- **Признак готовности** — для каждой цели определены покрывающие функции, критерий проверки и граница применимости.

## Заказчик и получатели результата

Проектная роль заказчика отведена авиакомпании, выполняющей прямые рейсы. Авиакомпания заинтересована в продаже доступных мест, согласованном учёте пассажирской и багажной вместимости и выполнении типовых операций с поездкой через личный кабинет. Владелец аккаунта оформляет и обслуживает бронирование. Пассажир получает право на перелёт после оформления билета и может совпадать с владельцем аккаунта.

Ожидаемая выгода для авиакомпании состоит в уменьшении числа конфликтов при распределении мест, исключении оформления билета без подтверждённой оплаты в пределах модели и возможности выполнять типовые операции самообслуживания. Фактическое изменение затрат и количества обращений определяется после измерения исходного уровня и результатов эксплуатации.

## Проверка необходимости и достаточности

**Необходимость.** Для каждой функции установлена связь хотя бы с одной целью. Например, без проверки документа возможна бронь для пассажира без подтверждённого допуска, без контроля закреплений возможна конфликтующая продажа места, а без учёта результата платёжной попытки невозможно обосновать выпуск билета.

**Достаточность в принятых границах.** Цели покрываются сквозными сценариями регистрации, покупки и обслуживания. Для каждой цели определены положительный сценарий и существенные отказы. На приёмке цепочка «цель → требование → сценарий → проверка» считается подтверждённой после воспроизводимого выполнения соответствующих испытаний. Границы оценки — прямые рейсы одной авиакомпании, одно бронирование на одного пассажира и согласованный перечень операций.

**Оценка выгоды.** Для сравнения с исходным процессом измеряются доля успешно завершённых операций самообслуживания, число конфликтующих закреплений и число обращений за ручным выполнением операций, доступных в системе. Для каждого показателя требуется одинаковое определение случая и сопоставимый период наблюдения. Целевые значения показателей эксплуатации уточняются с заказчиком.
