# 02. Вербальное описание предметной области

## Назначение документа

- **Задача** — описать порядок бронирования и изменения поездки в пределах одной авиакомпании.
- **Результат** — описание участников, объектов, основного процесса и существенных альтернатив.
- **Использование** — исходный материал для построения концептуальной модели данных и последующей проверки требований.
- **Признак готовности** — описание согласовано со словарём терминов и занимает не более трёх страниц в итоговой вёрстке.

## Участники, объекты и границы

Предметная область охватывает бронирование и приобретение билетов на прямые рейсы одной авиакомпании, а также изменение и отмену оформленной поездки. Прямой рейс связывает аэропорт отправления с аэропортом назначения. На каждом рейсе имеются места, доступность которых определяется с учётом действующих бронирований. Одно бронирование относится к одному пассажиру и одному рейсу на текущий момент.

Владелец аккаунта оформляет бронирование и осуществляет оплату. Пассажир — лицо, на которое оформляется билет. Владелец аккаунта может выступать пассажиром либо оформлять билет на лицо, добавленное в его список пассажиров. Данные аккаунта, сведения о личности пассажира и реквизиты его документов учитываются раздельно. Платёжный сервис принимает оплату и сообщает её результат.

## Бронирование и приобретение билета

Перед первым входом выполняется регистрация. Сервис регистрации создаёт учётную запись для входа и сообщает приложению результат. После успешной регистрации приложение создаёт связанный аккаунт, с которого в дальнейшем можно оформлять бронирования.

При входе приложение проверяет наличие связанного аккаунта по идентификатору входа в базе данных, затем проверяет учётные данные и предоставляет доступ только к личному кабинету соответствующего аккаунта после успешной проверки. В личном кабинете владелец просматривает список пассажиров, добавляет пассажиров, вносит реквизиты и загружает документы для себя или для пассажира из своего списка. Приложение направляет загруженные документы во внешний сервис проверки документов и сохраняет результат проверки каждого документа. Для покупки владелец просматривает сведения о рейсах и выбирает рейс. Затем он выбирает себя или пассажира из списка аккаунта, выбирает доступное место и указывает количество мест багажа.

Бронирование оформляется только после внесения реквизитов документа выбранного пассажира и получения положительного результата внешней проверки этого документа. При отрицательном результате или ожидании результата бронирование не создаётся. При оформлении за бронированием закрепляются выбранное пассажирское место и указанное количество мест багажа. В пределах одного рейса за одним местом может быть закреплено только одно действующее бронирование. Если место уже занято, оформление бронирования на это место отклоняется.

Сразу после оформления бронирования выполняется переход к оплате через внешний платёжный сервис. Полученный от него результат оплаты фиксируется. Пока окончательный результат неизвестен, пассажирское место и места багажа остаются закреплёнными. После подтверждения оплаты оформляется билет на выбранного пассажира, а сведения о билете предоставляются владельцу аккаунта. Если платёжная попытка окончательно завершилась без оплаты, бронирование прекращается, пассажирское место и места багажа освобождаются.

## Ограничения вместимости рейса

Для каждого рейса отдельно устанавливаются предельное количество пассажирских мест и предельное количество мест багажа. До начала оплаты проверяется наличие необходимых мест. Временно закреплённые места учитываются при определении доступного остатка. При недостаточной вместимости операция не оформляется.

## Просмотр бронирований и изменение поездки

Владелец аккаунта просматривает список оформленных с его аккаунта бронирований и открывает сведения о выбранном бронировании. В этих сведениях отражаются его текущее состояние и данные билета, если он оформлен. По приобретённому билету предоставляется маршрутная квитанция для просмотра, печати и отправки по электронной почте. Последующие действия владелец выполняет в отношении бронирований, оформленных с его аккаунта, и связанных с ними билетов.

После оплаты владелец аккаунта может без доплаты сменить место на том же рейсе. Прежнее место освобождается после успешной замены. Если новое место недоступно, прежнее сохраняется. После покупки можно добавить места багажа. До начала доплаты закрепляется запрошенное дополнительное количество мест. Оно включается в объём оплаченного багажа после подтверждения доплаты. Если платёжная попытка окончательно завершилась без доплаты, освобождаются только дополнительно закреплённые места.

Владелец аккаунта может отменить бронирование при соблюдении условий отмены. Подтверждённая отмена освобождает закреплённое пассажирское место и места багажа. По отменённому бронированию владелец аккаунта может подать запрос на возврат оплаты, если возврат допускается условиями приобретения билета. Владелец может просматривать состояние запроса, которое учитывается отдельно от состояния бронирования.

## Распределение ответственности

| Компонент или внешний сервис | Ответственность |
| --- | --- |
| Приложение | Создаёт связанный аккаунт после подтверждения регистрации. Проверяет учётные данные при входе. В личном кабинете принимает документы, направляет их на внешнюю проверку и сохраняет результаты. Ведёт сведения о пассажирах, проверяет наличие реквизитов и положительного результата проверки документа при бронировании, учитывает места, бронирования, билеты и запросы на возврат. |
| Сервис регистрации | Создаёт учётную запись для входа и передаёт приложению подтверждение регистрации и сведения для связи учётной записи с аккаунтом. |
| Внешний сервис проверки документов | Проверяет документы, загруженные в личном кабинете, и передаёт приложению результат проверки каждого документа. |
| Внешний платёжный сервис | Принимает оплату бронирования и доплату за багаж. Передаёт приложению результат каждой платёжной операции. |

Определения терминов приведены в [понятийном аппарате](02-terminology.md).
